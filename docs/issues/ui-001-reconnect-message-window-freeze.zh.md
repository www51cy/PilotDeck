# UI-001 服务重启后 WebSocket 重连，视图消息窗口冻结（表现为"对话消失"）

- 状态：待修复
- 发现日期：2026-11-07
- 发现方式：真实 Chrome（CDP 直连观察）+ 服务日志 + 磁盘 transcript 三方对照
- 影响面：开发/部署中服务进程重启后，所有已打开页面的当前会话视图

## 现象

服务整体重启后，前端页面仍停留在重启前的旧消息上：

- 消息计数器继续增长（实测 531 → 548 条），说明前端知道有新消息
- 但视图不渲染新消息，用户体感为"刚才聊的对话消失了"
- 无错误横幅、无报错提示
- 手动刷新页面后全部恢复

## 客观证据（2026-11-07 实测）

1. 10:19 Web(3001)/Gateway(18789)/Vite(5173) 三进程整体重启（新 pid 4617/4636/4680）
2. 重启后 WebSocket 反复断开重连，日志序列：
   `Chat client disconnected code=1001` → `WebSocket connection attempt` → `authenticated for user: cywin` → `Chat WebSocket connected`，02:44–02:49 至少 4 轮
3. 重连"成功"后，标签页 DOM 末条停在旧消息（"染导致崩溃…"），最新用户消息不在 DOM
4. 磁盘 transcript 完整：389 行、10 轮 accepted_input、最后写入 10:57——**数据零丢失，纯视图层故障**
5. 滚动容器位置正常（atBottom=true），排除"停在旧阅读位置"的正常行为

## 复现路径

1. 打开任意会话并停留在页面
2. 重启后端服务（kill 服务进程由 supervisor 拉起，或整机重启 dev 服务）
3. 等待 WebSocket 自动重连成功
4. 在另一终端向同会话发消息，或观察重连前未渲染的消息
5. 观察：计数器增长，视图不更新；刷新后恢复

## 期望行为

WebSocket 重连成功后，前端应重新对齐当前会话的消息状态：

- 重新拉取/重置当前会话消息窗口，使视图与服务端一致
- 或在检测到连接世代变化（connection generation）后明确触发一次全量同步
- 不允许"连接已恢复、视图却冻结"的静默状态

## 嫌疑点（待修复时定位确认）

- `ui/src/components/shell/utils/socket.ts`：WS 重连后的回调只恢复连接，未触发消息重新订阅
- 消息窗口/虚拟列表状态在重连后未重置
- 主会话消息加载 hook 缺少"重连后重新对齐"的副作用

## 验收标准

1. 服务重启 → WS 自动重连后，当前会话视图自动追平服务端消息，无需手动刷新
2. 重连期间产生的消息在重连后可见，顺序与 transcript 一致
3. 重连后继续发新消息，流式更新正常
4. 故障注入测试：模拟 WS close 1001 → 重连，断言视图消息数与 API 返回一致
5. revert 修复后该测试必须失败（回归测试要有牙）
