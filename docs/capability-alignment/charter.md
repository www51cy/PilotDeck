## 初衷

让 PilotDeck 在真实任务中成为可依赖、可恢复、可自动调用的智能体运行环境。对齐的是 Claude Code 的宿主能力，不是照搬源码、复制界面或改变底层模型能力。

工程必须按“对话随时可能被压缩”设计：对话摘要只作临时导航，项目工件、Git、源码和测试证据才是恢复与验收依据。持久化记录不提升事实性，也不创造新的授权。

## 总目标

1. 工具执行有闭合：逐项完成、唯一终态、中止可结算、迟到结果不污染、模型结果保序。
2. 子代理失败有边界：轮次与无进展有上限，父任务能识别失败原因，合法重试不被误伤。
3. 会话异常可恢复：刷新、重启、异常终止、重连和压缩前后状态一致，不静默丢失或重复执行。
4. 自动化结果可消费：非交互调用方能通过结构化结果和退出状态判断成败。
5. 权限边界可证明：最小范围授权，路径、符号链接和命令变体不能绕过。
6. 模块契约可替换：API、事件、会话、配置和令牌的共享关系显式化并有兼容验证。

## 方法

采用三层组合，不安装或照搬整套外部工具：

- 借鉴 Spec Kit 的工件化主线：章程、规格、计划、任务、实现、缺口收敛。
- 借鉴 EGM 的零上下文独立复核：复核者只读取规格、源码和证据，不继承实现者的对话判断。
- 用自动测试、故障注入、双协议对照和真实任务作为硬证据。

审查报告是中间产物，不是最终交付。每项发现必须修复、有证据反驳、明确留账或上交裁决；复审达到上限仍不收敛时不得自动视为委方接受。

## 状态语义

- `PASS`：规定范围内的实现、自动验证、真实任务和独立复核全部闭合。
- `PARTIAL`：已有部分有效证据，但仍有明确未覆盖场景或未闭合发现。
- `FAIL`：存在与规格矛盾的实测结果或明确回归。
- `UNVERIFIED`：尚无足够证据判断，不能写成完成。

测试通过只证明其实际覆盖范围；历史测试通过不自动证明当前工作区仍通过。

阶段内详细计划根据已取得的证据滚动细化，不提前编造后续实现细节，也不跳过阶段门。

## 当前授权边界

本轮仅授权阶段 0 的工程工件、基线测试、独立复核和本地提交。未授权业务行为修改、依赖安装、跨仓只读开放、历史数据改写、其他未提交工作的清理或远端推送。

本地提交只包含本工程明确拥有的文件；共享工作区中的外来修改必须保留。新阶段、新权限、公共协议变更和推送仍按既有治理边界处理。

## 恢复规则

任何会话继续本工程时，先读 `current-status.md`，再读能力矩阵和当前验收卡，随后核对 `git status`、相关提交、当前源码与测试证据。不得仅凭摘要或记忆宣布完成。
