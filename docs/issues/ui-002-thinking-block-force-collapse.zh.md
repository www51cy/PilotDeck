# UI-002 ThinkingBlock 流式结束瞬间强制折叠，覆盖用户手动展开状态

- 状态：待修复（语义待委方裁决）
- 发现日期：2026-11-07
- 发现方式：源码静态核查 + 历史真实运行态证据（2026-11-06 弹窗可见文本跳变实测）
- 影响面：子代理详情弹窗、主会话中所有流式 ThinkingBlock

## 现象

流式输出过程中，用户手动展开的 Thought process，在流式结束（isStreaming: true → false）的瞬间被自动折叠，用户展开的所有权被静默覆盖。历史实测中表现为弹窗可见文本反复跳变：65 → 375 → 114 → 985 → 147 字符。

## 机制实锤

`ui/src/components/chat-v2/ThinkingBlock.tsx:18`

```ts
// Reset the phase default during render, before paint.
if (view.streaming !== isStreaming) setView({ streaming: isStreaming, expanded: isStreaming });
```

流式相位一切换，`expanded` 被无条件写成 `isStreaming`（结束时即 false），不区分"默认值"与"用户手动值"。

同文件 :40 折叠态实现为 `<div hidden={!expanded}>`——内容继续挂载仅隐藏，大段 thinking 仍占 DOM，与 ToolRenderer 的折叠延迟挂载策略不统一。

## 测试缺口

现有 `ThinkingBlock.test.tsx` 只有一个用例，且把"结束自动折叠"固化为期望行为（:12 断言 aria-expanded=false）；**从未覆盖"流式运行中用户手动展开"这一真实场景**，因此该行为没有回归防线，也使行为变更缺乏测试约束。

## 历史现场证据（2026-11-06）

- 07:51 运行态实测：弹窗可见文本 65 → 375 → 114 → 985 → 147 跳变，滚动区一度 scrollHeight === clientHeight 失去滚动空间
- 07:55 代码级确认触发点即 `isStreaming: true → false` 时强制 expanded=false
- 用户原始诉求（11-06 #27）："页面不动了，刷新后才好，刷新前后内容不同、刷新前内容少"——本机制是主因之一

## 待裁决的期望语义（修复前必须先定）

二选一：

- **方案 A（手动展开优先）**：用户手动展开的块，流式结束后保持展开；只有从未被用户碰过的块，才在结束时默认折叠
- **方案 B（维持现状）**：流式结束统一折叠，但需在 UI 上给出内容仍可访问的明确提示，避免"内容变少"的丢失感

执行侧倾向 A，符合"折叠是视图状态、数据到达是事实"的既有设计约束。

## 验收标准（方案 A 为例）

1. 流式中手动展开 → 流式结束后仍保持展开
2. 未手动操作的块，结束后默认折叠（现状行为保留）
3. 折叠/展开在后续流式更新（若有）中不被意外重置
4. 新增组件测试覆盖：流式中展开→结束→断言 aria-expanded=true；revert 修复后该测试失败
5. 现有"未手动操作即自动折叠"用例保持通过

## 备注

- 本项是设计语义争议，不是单纯代码笔误，修复前须取得委方对 A/B 的明确裁决
